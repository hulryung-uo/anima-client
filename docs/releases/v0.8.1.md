# Anima v0.8.1 — More predictable account login

This testing draft includes v0.8.0's saved-world backups, settings restore,
connection isolation and sound/graphics cache improvements, plus fixes found
while checking the native login screen.

- Confirming a saved account or another menu option with Enter keeps you in the
  login screen. Enter on a file picker retains the normal file-selection action.
- Enter in a username or password field still connects. Confirming IME text or
  holding Enter no longer starts an unintended login.
- Connect stays disabled while account profiles are loading, need recovery or
  are being saved. A successful retry or completed save enables it again.
- A profile save or scene refresh cannot unlock a login request that is still
  pending. Ordinary request failures allow retry; profile-recovery errors keep
  Connect disabled until storage is available again.
- An existing character-selection session remains usable if profile storage
  becomes unavailable.

The full local quality gate passed for these fixes: 342 renderer tests, 23
Python tooling tests and the native/WASM checks. Regression tests reproduce the
failures in the previous source. The original Enter issue was observed in an
isolated macOS source build with synthetic accounts and a refused loopback
endpoint; the corrected behavior still needs an installed-app spot check.

This draft supersedes v0.8.0 for further testing. Its installer manifests and
workflow results record the exact source commit, signing and install checks.
Interactive checks on Windows and macOS, and current-build live-server gameplay,
disconnect and re-entry checks remain open. See the
[readiness audit](https://github.com/hulryung-uo/anima-client/blob/main/docs/CLIENT_READINESS.md)
and [v0.8.0 feature notes](https://github.com/hulryung-uo/anima-client/blob/main/docs/releases/v0.8.0.md).

Downloads target Apple Silicon macOS and Windows x64. Game data is not bundled.
Use your existing compatible Ultima Online client files and server account.
Optional saved passwords use the desktop OS credential store. This is a testing
draft, not a public release announcement.
