# v0.7.0 verification record

The installer source is tag `v0.7.0`, commit
`10aa94519ad62a77b8ded1073e8d54a495462bdd`. Later changes repair release tooling
and document validation; they do not move the tag or change its installer bytes.
The release remains a draft pending interactive and live-server checks.

## Evidence

| Check | Result and evidence |
| --- | --- |
| Tagged source quality | [CI 34711822404](https://github.com/hulryung-uo/anima-client/actions/runs/34711822404) passed on Linux, macOS and Windows. Includes Rust/WASM/web checks, desktop tests and profile regressions. |
| Actual Windows credential storage | The Windows CI job explicitly ran `native_profile_password_lifecycle -- --ignored`: one test passed. It covers save, preservation after a profile-write failure, replacement, restart reuse and deletion through Windows Credential Manager. This was a disposable runner credential, not a player's account. |
| Installer build and macOS signing | Both bundle jobs in [Release 34711822840](https://github.com/hulryung-uo/anima-client/actions/runs/34711822840) passed. The macOS app and DMG passed signature, notarization-ticket and Gatekeeper checks before hashing. The initial draft step failed with HTTP 403; this was not a build/signing failure. |
| Draft assembly | The `assemble` job in [34712577981](https://github.com/hulryung-uo/anima-client/actions/runs/34712577981) succeeded using those same artifacts after removing an unnecessary release target argument. Its first installer-check jobs could not read the private draft. Download access was subsequently isolated into a dedicated job. |
| Actual downloaded installers | [Installer checks 34712709301](https://github.com/hulryung-uo/anima-client/actions/runs/34712709301) passed on both platforms. Both downloads matched their commit, filename, size and SHA-256 manifests. macOS mounted the DMG, copied the app and checked version, architecture, signature and ticket. Windows silently installed 0.7.0 in a temporary folder and uninstalled it without launching the UI. |
| Local macOS copy | The downloaded DMG was also mounted locally; the copied app reports 0.7.0 / arm64, passes `codesign --verify --deep --strict`, `stapler validate` and Gatekeeper assessment. The release app process started and its loopback scene endpoint returned login state with no player. Native UI observation returned `cgWindowNotFound`, so this is not a graphical startup/login check. |

## Still required

- Interactive startup, layout/focus and saved-account login in the actual apps.
- Actual settings-file export/import and previous-copy restoration through a
  usable native window. Earlier browser automation lacked file access; no
  alternate UI-control method was used to bypass that restriction.
- Current-build gameplay, disconnect/re-entry and character operations against
  a live server. The local ServUO listener was offline and was not started or
  stopped for these tests.
- The broader [readiness audit](../CLIENT_READINESS.md), including profile
  recovery/export, character/window state isolation and long-session behavior.

These package and component checks establish neither complete client readiness
nor permission to label untested runtime behavior as verified.
