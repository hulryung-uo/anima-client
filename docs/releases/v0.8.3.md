# Anima v0.8.3 — Character window layouts

This testing draft includes the fast login and optional account/password saving
from earlier candidates, plus the following changes.

- Window positions and resizable window dimensions are remembered separately
  for each character. New layouts start from the existing common defaults, and
  all layouts are included in settings backups and recovery. Native layouts
  distinguish the configured server, shard, account and character; browser
  layouts distinguish the connected relay URL, account and character. Changing
  the destination behind an unchanged relay URL cannot be detected by the
  browser. Other preferences, including macros and HUD positions, remain common
  to the renderer origin. Different native window ports remain separate stores.
- A focused button keeps its keyboard input. Space and Tab no longer trigger
  game attack or war-mode shortcuts while operating buttons. Game canvas
  shortcuts and movement-key release behavior are preserved.
- Native UOP animation caching retains recently used groups instead of clearing
  every cached group at once. Retained payloads are limited to 16 entries and
  64 MiB. Larger custom animations remain readable without caching; this is not
  a whole-process memory or decoding limit.
- Malformed UOP directory cycles and invalid active entry addresses are rejected
  instead of leaving file traversal running indefinitely.

## Testing status

The full local quality gate passed, covering native, WASM, desktop, tooling and
370 renderer tests with 1,845 assertions. Real UO data tests verified eager/lazy
UOP reading and animation frame resolution. An isolated real-browser fixture
verified two character layouts saving and restoring different positions and
sizes, using the production window/storage code and the browser's ResizeObserver.
A native loopback login fixture verified layout identity without including the
password. These fixtures do not establish live-shard gameplay readiness.

This version's installer build, signing and installation results are recorded
in its manifests and workflow. Current installed-app interaction, live-character
switching, movement/combat/inventory flows, disconnect/re-entry and long-session
verification remain open. See the
[readiness audit](https://github.com/hulryung-uo/anima-client/blob/main/docs/CLIENT_READINESS.md).

Downloads target Apple Silicon macOS and Windows x64. Game data is not bundled.
This remains a testing draft; public release and feature announcements require
the outstanding acceptance checks.
